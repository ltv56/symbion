# Database schema

MySQL 8, InnoDB, utf8mb4. Migrations are hand-written SQL in `apps/api/src/migrations/`.

## merchants

| Column         | Type                | Notes                                                      |
| -------------- | ------------------- | ---------------------------------------------------------- |
| `id`           | BIGINT UNSIGNED, PK | auto increment                                             |
| `name`         | VARCHAR(255)        |                                                            |
| `api_key_hash` | CHAR(64), UNIQUE    | SHA-256 hex digest (64 chars); the raw key is never stored |
| `created_at`   | TIMESTAMP           | defaults to now                                            |

API keys: 32 random bytes (64 hex chars), generated by `POST /merchants` and `POST /merchants/:id/api-key` (replaces the old key), returned once. Only the SHA-256 hash is stored; lookup is by `api_key_hash`.

## tiers

Global: managed by the app admin, shared by all merchants (no `merchant_id`).

| Column      | Type                    | Notes                                                                           |
| ----------- | ----------------------- | ------------------------------------------------------------------------------- |
| `id`        | BIGINT UNSIGNED, PK     | auto increment                                                                  |
| `name`      | VARCHAR(255), UNIQUE    | e.g. silver, gold                                                               |
| `min_spend` | BIGINT UNSIGNED, UNIQUE | 12-month spend in VND to reach this tier                                        |
| `earn_rate` | DECIMAL(5,2)            | tier multiplier, e.g. 1.25 (see [rules](../rules.md)); `CHECK (earn_rate >= 0)` |

## members

`email` is unique across the programme (points are shared across merchants).

| Column        | Type                 | Notes                                                    |
| ------------- | -------------------- | -------------------------------------------------------- |
| `id`          | BIGINT UNSIGNED, PK  | auto increment                                           |
| `merchant_id` | BIGINT UNSIGNED, FK  | `merchants(id)`; the merchant where the member signed up |
| `tier_id`     | BIGINT UNSIGNED, FK  | `tiers(id)`                                              |
| `email`       | VARCHAR(255), UNIQUE |                                                          |
| `name`        | VARCHAR(255), null   |                                                          |
| `created_at`  | TIMESTAMP            | defaults to now                                          |

No auth columns; members are identified by email and log in with a one-time code (`member_otps`). `merchant_id` is the merchant whose API key created the member.

## member_otps

At most one live code per member; a new request replaces the row, a successful login deletes it.

| Column       | Type                    | Notes                                                       |
| ------------ | ----------------------- | ----------------------------------------------------------- |
| `member_id`  | BIGINT UNSIGNED, PK, FK | `members(id)`, `ON DELETE CASCADE`                          |
| `code_hash`  | CHAR(64) ascii          | HMAC-SHA256 of `<member_id>:<code>` keyed with `JWT_SECRET` |
| `attempts`   | TINYINT UNSIGNED        | wrong codes so far; the row is deleted at 5                 |
| `expires_at` | TIMESTAMP               | 5 minutes after the request                                 |
| `created_at` | TIMESTAMP               | time of the latest request                                  |

## orders

| Column            | Type                | Notes                                 |
| ----------------- | ------------------- | ------------------------------------- |
| `id`              | BIGINT UNSIGNED, PK | auto increment                        |
| `merchant_id`     | BIGINT UNSIGNED, FK | `merchants(id)`; set from the API key |
| `member_id`       | BIGINT UNSIGNED, FK | `members(id)`                         |
| `idempotency_key` | VARCHAR(255)        | chosen by the merchant per order      |
| `amount`          | BIGINT UNSIGNED     | whole VND                             |
| `created_at`      | TIMESTAMP           | defaults to now                       |

`UNIQUE (merchant_id, idempotency_key)` (`uq_orders_merchant_idempotency_key`) is the last line of defence against duplicate orders. `idempotency_key` is `utf8mb4_bin` (case sensitive) and unique per merchant only.

## ledger_lots

One row per lot (see `packages/ledger`). Rows are never deleted; only `remaining` changes.

| Column            | Type                        | Notes                                                            |
| ----------------- | --------------------------- | ---------------------------------------------------------------- |
| `id`              | BIGINT UNSIGNED, PK         | auto increment; FIFO ties are broken by lower id                 |
| `merchant_id`     | BIGINT UNSIGNED, FK         | merchant that sent the order or spend                            |
| `member_id`       | BIGINT UNSIGNED, FK         |                                                                  |
| `points`          | BIGINT                      | signed: negative for spend entries; `CHECK (points <> 0)`        |
| `remaining`       | BIGINT                      | signed: points not spent yet; negative for a debt lot            |
| `expires_at`      | DATETIME, NULL              | NULL never expires; debt lots ignore it                          |
| `idempotency_key` | VARCHAR(255), `utf8mb4_bin` | case sensitive; earn and spend keys share one space per merchant |
| `created_at`      | TIMESTAMP                   | defaults to now                                                  |
| `type`            | VARCHAR(16)                 | `earn` (points > 0) or `spend` (points < 0); `CHECK`             |
| `ref_type`        | VARCHAR(32), NULL           | source of the lot, e.g. `order`                                  |
| `ref_id`          | BIGINT UNSIGNED, NULL       | id of the source row; NULL together with `ref_type` (`CHECK`)    |

`UNIQUE (merchant_id, idempotency_key)` is the last line of defence for a repeated earn or spend. Index `(member_id, expires_at, id)` serves the FIFO read. `ref_type` is `order` for lots awarded for an order, `redemption` for the spend of a redemption and `refund` for the deduction of a refund; `ref_id` is the id in `orders`, `redemptions` or `refunds`.

## program_settings

Programme-wide values. Exactly one row (`id = 1`), inserted by the migration.

| Column            | Type                 | Notes                                                                      |
| ----------------- | -------------------- | -------------------------------------------------------------------------- |
| `id`              | TINYINT UNSIGNED, PK | `CHECK (id = 1)`                                                           |
| `point_value_vnd` | INT UNSIGNED         | VND the app pays a merchant per redeemed point; `CHECK (> 0)`, default 100 |

## vouchers

| Column         | Type                | Notes                                                   |
| -------------- | ------------------- | ------------------------------------------------------- |
| `id`           | BIGINT UNSIGNED, PK | auto increment                                          |
| `merchant_id`  | BIGINT UNSIGNED, FK | `merchants(id)`; the merchant where the voucher is used |
| `title`        | VARCHAR(255)        |                                                         |
| `face_value`   | BIGINT UNSIGNED     | VND discount; `CHECK (face_value > 0)`                  |
| `points_price` | BIGINT UNSIGNED     | points a member pays; `CHECK (points_price > 0)`        |
| `stock`        | INT UNSIGNED        | vouchers left                                           |
| `valid_until`  | TIMESTAMP           | not redeemable after this time                          |
| `status`       | VARCHAR(16)         | `active` (default) or `expired`; `CHECK`                |
| `created_at`   | TIMESTAMP           | defaults to now                                         |

`face_value >= points_price × point_value_vnd` is enforced by the API (a `CHECK` cannot read `program_settings`). Index `(status, id)` serves the list of active vouchers.

## redemptions

| Column            | Type                         | Notes                                                           |
| ----------------- | ---------------------------- | --------------------------------------------------------------- |
| `id`              | BIGINT UNSIGNED, PK          | auto increment                                                  |
| `merchant_id`     | BIGINT UNSIGNED, FK          | `merchants(id)`; the voucher's merchant                         |
| `member_id`       | BIGINT UNSIGNED, FK          | `members(id)`                                                   |
| `voucher_id`      | BIGINT UNSIGNED, FK          | `vouchers(id)`                                                  |
| `code`            | VARCHAR(16) ascii, ascii_bin | unique; 10 characters of Crockford base32, upper case           |
| `points`          | BIGINT UNSIGNED              | `points_price` at redemption; `CHECK (> 0)`                     |
| `point_value_vnd` | INT UNSIGNED                 | `program_settings.point_value_vnd` at redemption; `CHECK (> 0)` |
| `status`          | VARCHAR(16)                  | `issued` (default) or `used`; `CHECK`                           |
| `client_key`      | VARCHAR(255), utf8mb4_bin    | the request's `Idempotency-Key`                                 |
| `used_at`         | TIMESTAMP NULL               | set when confirmed; `CHECK` non-null exactly when `used`        |
| `expires_at`      | TIMESTAMP                    | `LEAST(created_at + 30 days, vouchers.valid_until)`             |
| `created_at`      | TIMESTAMP                    | defaults to now                                                 |

`expired` is not stored: the API reports `issued` past `expires_at` as `expired`. `UNIQUE (member_id, client_key)`. The ledger spend of a redemption has key `redemption:<id>` and the voucher's `merchant_id`.

## refunds

| Column            | Type                      | Notes                                 |
| ----------------- | ------------------------- | ------------------------------------- |
| `id`              | BIGINT UNSIGNED, PK       | auto increment                        |
| `merchant_id`     | BIGINT UNSIGNED, FK       | `merchants(id)`; the order's merchant |
| `order_id`        | BIGINT UNSIGNED, FK       | `orders(id)`                          |
| `idempotency_key` | VARCHAR(255), utf8mb4_bin | the request's `Idempotency-Key`       |
| `amount`          | BIGINT UNSIGNED           | VND refunded; `CHECK (> 0)`           |
| `points_deducted` | BIGINT UNSIGNED           | points taken back by this refund      |
| `created_at`      | TIMESTAMP                 | defaults to now                       |

`UNIQUE (merchant_id, idempotency_key)`. The ledger spend of a refund has key `refund:<id>` and the order's `merchant_id`; none is written when `points_deducted` is 0.
